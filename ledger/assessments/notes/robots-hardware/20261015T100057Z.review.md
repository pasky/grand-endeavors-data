## Minor findings

1. **Input-range notation, especially Blue Collar/Dark Line:** `lnorm(med, lo, hi)` uses `lo` and `hi` to set a symmetric log-width; these are not generally its actual 10th/90th percentiles. For example, task failures `(0.15, 0.08, 0.5)` imply approximately 0.060–0.375, and other assists `(0.3, 0.05, 1.5)` imply 0.055–1.643. Clarify the convention or report actual percentiles rather than calling every pair an 80% interval. This is a description of the retained, reproducible assumed distributions, not grounds for an unattributed refit.
2. **Sensitivity/register completeness:** Add an explicit assumed label and low/high sensitivity for Wozniak's LEAP log-SD 0.49 and its remapping; current rows vary the blend weight but do not isolate these choices. Blue Collar component sensitivities are largely grouped into I0 or shown only for Dark Line. S0 and M_MISS could also have per-target low/high results. Existing mapping and failure sensitivities cover the principal cruxes; these are incomplete minor sensitivities, not hidden measured inputs.
3. **Fukushima presentation:** The label says the valve was not done, whereas the effective event says completion was not reported. Use “valve closure unreported.” Also correct the illustrative point calculation: a joint probability of 0.08 gives odds 0.08/0.92 ≈ 0.087, not 0.075. The executable model uses the correct `pj0/(1-pj0)` expression, so this prose correction does not change the reproduced forecast.

For Robotaxi context, make explicit that Baidu's >250,000 rides/week is system-wide across 22 cities, while the >1,000-vehicle figure is Wuhan-specific (`2025-11-01-baidu-apollo-go-weekly-rides-rv`).
