## Method (all five challenges)

- Prev: none. No earlier assessment of any health challenge exists in ledger/assessments/health.jsonl
  (only kpi and milestone records), so `basis.prev` is null and rule 7 / rule 1 constrain nothing.
- Evidence: effective events in ledger/events/health.jsonl with published <= 2026-10-28 (375 records,
  304 effective after removing superseded ones and withdrawal tombstones), filtered to those tagged with
  the challenge. Window (2025-10-28, 2026-10-28]: an event counts if its date overlaps it (partial dates
  end no later than publication). Results that happened before the window but carry a "2025" date
  (re-verified legacy backfill, e.g. Eisai etalanetug, ITP review, rapamycin+trametinib) were left out
  because the result itself predates the window; legacy events were used for context only.
- Each window event classified: advance (substantive or not), setback, or not an advance
  (funding, deals, plans, IND clearances, regulatory process, policy, neighbouring problems).
  Substantive = step change from a verified event resting on more than the proponent's word
  (peer review, regulator review, independent replication). Company toplines/conference data never
  substantive. Events not counted.
- Order of verdicts: unknown -> Setback (setbacks outweigh advances) -> Advancing -> Inching -> Stalled.
