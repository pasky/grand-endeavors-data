### 0.2 Shared transfer term T (audit robots-software-current #3/#4; cross-section "inconsistent evidence bar")

Every milestone maps a real-world effort (expert hours of a kernel series, of a Nature paper, of a
work-week of business operations) onto METR horizon minutes. That mapping is a **core link** (RUBRIC
v5 §4.1 step 3): an unmeasured penalty is not zero by default. The previous runs set it to a
median-zero range term; the audit (#4: "excluding unsupported discounts does not establish zero median
transfer penalty") is right under v5.

- **Sourced direction and size**: Kwa et al. 2025 (METR, arXiv 2503.14499v3, §4/C.2/F.2): on METR's
  internal PRs "contractors tak[e] 5–18x longer to fix issues than repo maintainers", and "AI agent
  performance is worse than would be predicted by maintainer time-to-complete ... but is consistent
  with contractor time-to-complete"; "models perform worse on tasks that have higher messiness scores",
  while "trends ... are similar for the lower and higher messiness subsets". So METR minutes are
  low-context-baseliner minutes on cleaner tasks; real expert-hours of messy work need *more* METR
  minutes, and the growth rate transfers.
- **Central value (assumed)**: T = +1 doubling (×2). Reasoning: the 5–18× gap was measured on small
  PRs where context acquisition dominates; for person-month-to-person-year tasks the ramp-up cost
  amortises (a skilled newcomer is perhaps 1.5–3× slower over a large project), and messiness lowers
  success at a given length; against this, the milestones allow selection, retries and iteration with
  reviewer/customer feedback, which lowers the reliability actually needed.
- **Range (assumed)**: split-normal in doublings, p10 −0.5 (selection/scaffolding outweigh), p90 +3
  (the full small-PR 5–18× factor plus messiness persists at scale).
- **Same T for all three** (audit #4: shared METR inputs centralised, transfer justified
  consistently). Milestone-specific mapping terms are argued per milestone (Nature keeps a
  median-zero significance range term). T **replaces** the previous kernel/solo median-zero
  "real-codebase"/"benchmark-to-business" N(0,1) terms (no stacking).
- **Measured?** No. Transfer-validation criteria (what would measure it): METR-style horizons
  scored against maintainer time on real repositories (a replication of the internal-PR study at
  multi-day lengths), mergeability rates of agent PRs in large projects, and logged intervention
  rates of agent-run business operations. Sensitivity: T = 0 → p50 −0.35/−0.36/−0.44 yr; T = +3 →
  +0.56/+0.55/+0.67 yr (kernel/Nature/solo, MC medians). Not a >2-yr crux, but it is the mapping, so
  it heads each crux list.

# Window statistics for the METR by-release series (shared METR fit, as of 2026-10-14).
# Reads `ledger.py series robots-software <metric> --as-of 2026-10-14`, drops month-only
# duplicate rows (YYYY-MM, which repeat a dated row), takes the running-max frontier by release
# date, and fits OLS of log2(minutes) on time (months) over the in-window points.
import subprocess, math, datetime as dt
import numpy as np
from scipy import stats

ROOT = "/home/pasky/projects/hai/grand-endeavors-agent-worktree-0005"
AS_OF = "2026-10-14"

def series(metric):
    out = subprocess.run(["uv", "run", f"{ROOT}/core/ledger.py", "series", "robots-software", metric,
                          "--as-of", AS_OF], capture_output=True, text=True, cwd=f"{ROOT}/data").stdout
    pts = []
    for line in out.strip().splitlines():
        d, v = line.split(",")[:2]
        if len(d) == 7:  # month-only duplicate
            continue
        pts.append((dt.date.fromisoformat(d), float(v)))
    pts.sort()
    fr, best = [], 0
    for d, v in pts:
        if v > best:
            fr.append((d, v)); best = v
    return fr

def yr(d):
    return d.year + (d.timetuple().tm_yday - 1) / 365.25

def ols(pts):
    x = np.array([yr(d) * 12 for d, _ in pts]); y = np.log2([v for _, v in pts])
    r = stats.linregress(x, y)
    n = len(pts); t = stats.t.ppf(0.975, n - 2)
    lo, hi = r.slope - t * r.stderr, r.slope + t * r.stderr
    dbl = 1 / r.slope
    ci = (1 / hi if hi > 0 else None, 1 / lo if lo > 0 else None)
    return dbl, ci, r

def window(fr, a, b, label):
    a, b = dt.date.fromisoformat(a), dt.date.fromisoformat(b)
    w = [(d, v) for d, v in fr if a <= d <= b]
    prior = [(d, v) for d, v in fr if d < a]
    start = prior[-1][1] if prior else w[0][1]
    last_d, last_v = w[-1]
    s_l = (yr(last_d) - yr(a)) * 12 / math.log2(last_v / start)
    dbl, ci, r = ols(w) if len(w) >= 3 else (None, (None, None), None)
    cis = f"{ci[0]:.2f}-{ci[1]:.2f}" if ci[0] and ci[1] else f"{ci[0] and round(ci[0],2)}-{ci[1] and round(ci[1],2)}"
    print(f" {label} {a}..{b} n={len(w)} start {start} -> last ({last_d}, {last_v}) x{last_v/start:.2f}; "
          f"start->last dbl {s_l:.2f} mo; OLS {dbl:.2f} CI {cis}")
    return dbl, ci, r, w

for m in ["metr-80-horizon-by-release", "metr-50-horizon-by-release"]:
    fr = series(m)
    print("==", m, len(fr), "frontier pts:", ", ".join(f"{d} {v}" for d, v in fr))
    dbl, ci, r, w = window(fr, "2024-10-14", "2026-10-14", "current")
    lastd, lastv = w[-1]
    fit = 2 ** (r.intercept + r.slope * yr(lastd) * 12)
    print(f"   OLS fitted at last pt {fit:.1f} (observed {lastv}; {math.log2(lastv/fit):+.2f} doublings)")
    window(fr, "2022-10-14", "2024-10-14", "previous")
    window(fr, "2024-10-14", "2025-10-14", "h1")
    window(fr, "2025-10-14", "2026-10-14", "h2")
    d_all, ci_all, _ = ols(fr)
    print(f" long-run all n={len(fr)} OLS {d_all:.2f} CI {ci_all[0]:.2f}-{ci_all[1]:.2f}")
